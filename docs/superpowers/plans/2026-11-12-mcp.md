# Moaney MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose all agreed Moaney finance operations through authenticated MCP with reviewable, retry-safe changes.
**Architecture:** Opt-in remote endpoint in the existing Express process. OAuth and durable drafts live in SQLite; the official SDK serves typed tools backed by existing domain functions.
**Tech Stack:** Node 22+, TypeScript, Express 4, Drizzle/better-sqlite3, Zod 4, MCP SDK v2, Vitest/Supertest.
**Spec:** ../specs/2026-11-12-mcp-design.md

## Global Constraints
- Existing browser sessions and REST behavior remain intact.
- Money inputs are decimal rupiah strings; outputs declare integer minor units and exponent 2.
- Maximum 100 operations per draft; immutable, client-bound, expiring drafts and durable receipts.
- No live database writes, deploys, pushes, or commits without a separate user request.

## Review Focus
- PKCE, exact redirects, CSRF, resource/scope binding and refresh replay are exercised by OAuth integration tests.
- A failed operation must roll back all batch operations and their audit/journal effects.
- Retrying after process restart must return the original receipt.
- Concurrent app edits must invalidate a draft before writing.
- Every operation family must validate references, preserve existing ledger invariants and label money units.
